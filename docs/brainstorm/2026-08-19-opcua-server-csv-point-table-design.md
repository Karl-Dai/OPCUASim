# OPC UA 子站 CSV 点表导入设计

- 日期：2026-08-19
- 状态：已在对话中确认
- 目标应用：OPCUASim 子站（Server）

## 1. 背景

当前子站支持手工新增目录和变量，也支持通过 `.opcuaproj` 保存、加载完整项目，但没有面向现场点表的 CSV 导入入口。

设计参考文件 `config_7517_AGC_1.db` 中共有 78 个协议明细点，其中 73 个点填写了唯一的数字 `opcuaId`。参考点表使用的 OPC UA 数据类型均为标量类型，且同时包含只读测量点和 AGC 启停、功率设定等可写命令点。

## 2. 目标

1. 提供一个适合 Excel 编辑、结构简单且版本明确的 CSV 点表格式。
2. 每个 CSV 数据行描述一个 OPC UA 变量点；目录由路径自动生成。
3. 将 `opcua_id=10417` 映射为子站运行时命名空间内的数字 NodeId，即 `ns=<运行时命名空间索引>;i=10417`。
4. 在修改当前点表前完成全文件校验，保证失败时现有目录和节点完全不变。
5. 将 CSV 作为完整点表快照，确认导入后原子替换现有目录和变量，但保留服务器配置。
6. 保持已有 `.opcuaproj` 文件向后兼容。

## 3. 非目标

本次设计不包含：

- 端点地址、监听端口、安全策略、用户、证书等服务器配置。
- 子站运行期间导入或热替换地址空间。
- CSV 增量合并、追加导入或按行覆盖。
- 数组、二维数组、枚举和结构体等复杂 OPC UA 数据类型。
- Random、Sine、Linear、Script 等动态仿真配置。
- 对 `POWER`、`CALC`、`PITCHANGLE`、`STOPCOMMAND` 等外部系统专用生成器的兼容。
- 直接导入 SQLite 数据库或其他厂商私有点表格式。
- CSV 点表导出。

## 4. CSV 文件契约

### 4.1 编码与语法

- 文件扩展名为 `.csv`。
- 使用 UTF-8 编码；允许开头存在 UTF-8 BOM，以兼容 Excel 中文编辑。
- 分隔符固定为英文逗号 `,`。
- 字段引用、字段内逗号、双引号和换行遵循 RFC 4180 转义规则。
- 第一行必须是固定表头；允许空白数据行，但不支持注释行。
- 除表头和空白行外，文件必须至少包含一个有效测点行；空点表不能用于清空当前项目。
- 最大文件大小为 20 MiB，最多 100,000 个数据行，单字段解码后最大 4,096 个字符。
- 不允许缺少、重复或额外的表头字段，以避免拼写错误被静默忽略。

固定表头如下：

```csv
format_version,opcua_id,folder_path,browse_name,display_name,data_type,writable,initial_value
```

### 4.2 字段定义

| 字段 | 必填 | 规则 |
|---|---:|---|
| `format_version` | 是 | 每行固定为 `1`；同一文件不允许混用版本。 |
| `opcua_id` | 是 | 十进制无符号整数，范围 `1..4294967295`，全文件唯一。 |
| `folder_path` | 否 | 使用 `/` 分隔层级；空值表示 OPC UA `Objects` 目录。 |
| `browse_name` | 是 | 当前目录下的 BrowseName；去除首尾空白后不能为空。 |
| `display_name` | 是 | 节点显示名称；允许中文，去除首尾空白后不能为空。 |
| `data_type` | 是 | 支持的标量类型或兼容别名，见 4.4。 |
| `writable` | 是 | 仅接受不区分大小写的 `true` 或 `false`。 |
| `initial_value` | 否 | Static 初始值；空值使用数据类型默认值，见 4.5。 |

### 4.3 目录生成

`folder_path` 采用 `/` 分层，例如：

```text
WTUR/PwrAt/Ra/F32
```

导入器按从左到右的顺序创建 `WTUR`、`PwrAt`、`Ra` 和 `F32` 四级目录：

- 路径整体和每个分段都去除首尾空白。
- 禁止空分段、`.`、`..`、控制字符和分段内的 `/`。
- 相同的规范化路径只创建一次。
- 同一父目录下不允许出现重复的 `browse_name`，包括目录与变量之间的重名。
- 目录使用稳定的内部字符串 NodeId：`folder:/<规范化完整路径>`。
- 目录的 BrowseName 和 DisplayName 均使用当前路径分段的原文。

变量使用独立的数字标识，不从 `folder_path` 或 `browse_name` 推导 NodeId。

### 4.4 数据类型

规范类型名和参考点表别名如下：

| CSV 输入 | 子站内部类型 |
|---|---|
| `Boolean`、`BOOL` | `Boolean` |
| `Int16`、`INT` | `Int16` |
| `Int32`、`DINT` | `Int32` |
| `Int64` | `Int64` |
| `UInt16`、`UINT` | `UInt16` |
| `UInt32`、`UDINT`、`DWORD` | `UInt32` |
| `UInt64` | `UInt64` |
| `Float`、`REAL` | `Float` |
| `Double`、`LREAL` | `Double` |
| `String`、`STRING`、`STRING(n)` | `String` |
| `DateTime` | `DateTime` |
| `ByteString` | `ByteString` |

类型匹配不区分大小写。`STRING(n)` 中的 `n` 必须是正整数；该长度只用于兼容外部点表，子站不强制字符串长度，预检结果应显示一条非阻断警告。

数组、枚举、结构体和未识别类型均为阻断错误。

### 4.5 初始值和默认节点属性

所有 CSV 导入节点统一使用 `Static` 仿真模式。`initial_value` 的解析规则为：

| 数据类型 | 非空值规则 | 空值默认值 |
|---|---|---|
| `Boolean` | `true` 或 `false`，不区分大小写 | `false` |
| 有符号/无符号整数 | 十进制整数，且必须在目标类型范围内 | `0` |
| `Float`、`Double` | 有限十进制数；拒绝 NaN 和无穷大 | `0` |
| `String` | CSV 解码后的原始字符串 | 空字符串 |
| `DateTime` | RFC 3339 时间字符串 | `1970-01-01T00:00:00Z` |
| `ByteString` | Base64 字符串 | 空字节串 |

其他默认属性：

- `writable` 严格取自 CSV，不根据 IECPath、目录名或 BrowseName 推断。
- 数值节点的 `eu_range_low` 和 `eu_range_high` 沿用当前默认值 `0` 和 `100`。
- 动态仿真模式可在导入完成后通过现有属性编辑界面设置。

### 4.6 示例

```csv
format_version,opcua_id,folder_path,browse_name,display_name,data_type,writable,initial_value
1,48,WTUR/PwrAt/Ra/F32,RatedPower,风机额定功率,LREAL,false,3000
1,10417,WTUR/Bool/Wd/b0,AGCconverterreset,AGC平台复位指令,BOOL,true,false
1,14447,WNAC/Temp/Ra,F32,机舱温度,REAL,false,25
1,1682,WTUR/Other/Rg/S,Plcversion,风机主控程序版本号,STRING(80),false,"V1.0,AGC"
```

## 5. 预检与校验

### 5.1 校验原则

解析器必须先读取并校验完整文件，再构造待提交的目录和节点集合。任何阻断错误都会使整次导入不可确认，当前项目状态不得发生变化。

至少校验：

1. 文件编码、大小、CSV 语法和固定表头。
2. `format_version` 是否全部为 `1`。
3. 必填字段、字段长度和条件格式。
4. `opcua_id` 范围、格式及全文件唯一性。
5. `folder_path` 规范性及目录生成冲突。
6. 同一父目录下 BrowseName 是否冲突。
7. 数据类型是否受支持。
8. `writable` 是否为合法布尔值。
9. `initial_value` 是否能无损转换到目标数据类型。

### 5.2 错误呈现

每个问题包含：

- 严重级别：`error` 或 `warning`。
- CSV 物理行号；文件级问题不带行号。
- 字段名。
- 稳定错误码。
- 面向用户的本地化说明。

一次预检最多返回前 200 个问题，并通过 `truncated=true` 表示还有未展示的问题。错误信息不得只返回底层 Rust、Serde 或 CSV 库文本。

预检摘要至少包含：

- 文件指纹。
- 有效测点数。
- 自动生成目录数。
- 只读点数和可写点数。
- 错误数和警告数。

## 6. 导入语义与交互

### 6.1 状态限制

- 仅当子站状态为 `Stopped` 时允许选择和导入 CSV。
- `Running`、`Starting` 或 `Stopping` 状态下导入按钮禁用，并显示原因。
- 导入成功后不自动启动子站。

### 6.2 两阶段流程

1. 用户点击工具栏“导入 CSV”。
2. 文件选择器仅显示 `.csv` 文件。
3. 后端读取文件、执行全量预检并计算 SHA-256 文件指纹。
4. 对话框显示测点、目录、读写属性和问题摘要。
5. 存在阻断错误时不显示确认导入操作。
6. 零错误时明确提示“将替换当前全部目录和测点，但不会修改服务器配置”。
7. 用户确认后，后端重新读取文件、重新校验，并比较文件指纹。
8. 文件变化、子站状态变化或重新校验失败时中止，不修改现有点表。
9. 校验通过后，一次性替换目录和节点集合，刷新地址空间视图。

预检不会修改内存状态、磁盘项目文件或服务器配置。导入也不会自动保存 `.opcuaproj`；用户仍通过现有“保存项目”操作决定是否持久化。

### 6.3 原子性

新目录和节点必须在临时集合中完整构造。只有全部构造成功后，才在单个提交阶段替换 `AppState.folders` 和 `AppState.nodes`。实现不得逐行调用现有 `add_folder` 或 `add_node` 命令，否则中途失败会留下部分导入结果。

由于仅允许在 `Stopped` 状态导入，提交阶段不直接修改正在运行的 OPC UA 地址空间。下一次启动服务器时使用新的完整节点集合构建地址空间。

## 7. 内部模型与组件边界

### 7.1 数字 NodeId

当前 `ServerNode.node_id` 是字符串，普通 `"10417"` 会生成字符串 NodeId。为表达数字 NodeId，增加带默认值的标识类型字段：

```rust
enum NodeIdKind {
    String,
    Numeric,
}

struct ServerNode {
    node_id: String,
    #[serde(default)]
    node_id_kind: NodeIdKind,
    // existing fields...
}
```

- `NodeIdKind::default()` 为 `String`，保证旧 `.opcuaproj` 文件含义不变。
- CSV 导入节点保存 `node_id=opcua_id.to_string()` 和 `node_id_kind=Numeric`。
- 构建地址空间时，`Numeric` 使用运行时命名空间索引和解析后的 `u32` 创建 NodeId。
- 手工新增节点继续默认使用 `String`。
- 节点表和属性编辑器应将数字节点显示为 `i=<id>`，不写死 `ns=2`。
- `.opcuaproj` 保存并恢复 `node_id_kind`，确保数字 NodeId 往返不变。
- 应用层节点身份由 `(node_id_kind, node_id)` 二元组组成；节点 DTO 以及更新、删除等变更请求都必须携带标识类型，不能继续只按裸字符串匹配。
- 旧前端或旧项目缺少 `node_id_kind` 时按 `String` 处理。界面分别显示 `s=<id>` 和 `i=<id>`，避免同文本的字符串、数字标识产生歧义。
- 所有创建、删除、仿真值更新和地址空间查找路径必须使用同一二元身份规则。

### 7.2 核心解析器

在 `opcuasim-core` 中新增独立点表模块，职责仅包括：

- CSV 解码和版本识别。
- 行 DTO 解析。
- 类型别名和初始值转换。
- 目录规范化与生成。
- 全文件交叉校验。
- 输出预检结果或完整的 `Vec<ServerFolder>`、`Vec<ServerNode>`。

解析器不依赖 Tauri、文件选择器、全局应用状态或正在运行的服务器，便于独立单元测试。

### 7.3 应用命令

子站应用层提供两个命令：

```text
preview_point_table(path) -> PointTablePreview
import_point_table(path, fingerprint) -> AddressSpace
```

`preview_point_table` 只读文件。`import_point_table` 负责状态检查、重新验证、指纹比较和原子提交，不在前端复制校验规则。

### 7.4 前端

- `Toolbar.vue` 增加“导入 CSV”按钮。
- 新建职责单一的 `ImportPointTableDialog.vue`，展示文件信息、统计、错误表和最终确认。
- 新增中英文文案及错误码映射。
- 现有服务器配置对话框和 `.opcuaproj` 加载流程保持独立。

## 8. 错误处理

以下情况均不得修改当前点表：

- 文件不存在、无法读取或不是有效 UTF-8。
- 文件过大、行数或字段长度超过限制。
- CSV 语法或表头错误。
- 任一行存在阻断错误。
- 用户在预检后修改了文件。
- 用户确认前子站状态离开 `Stopped`。
- 临时目录或节点集合构造失败。

提交阶段只执行内存集合替换，不包含文件写入、服务器启动或网络调用。若提交前的任一步骤失败，直接丢弃临时结果。

## 9. 测试与验证

### 9.1 解析器单元测试

- UTF-8、UTF-8 BOM、中文、CRLF/LF。
- 带逗号、双引号和换行的合法引用字段。
- 固定表头、缺列、重复列、额外列和错误版本。
- 所有规范标量类型及参考库类型别名。
- 各类型空初始值和合法、越界、非法初始值。
- `opcua_id` 的边界值、重复值、非数字和零值。
- 目录规范化、非法路径、目录复用和 BrowseName 冲突。
- `STRING(n)` 非阻断警告。
- 文件大小、行数、字段长度和问题数量上限。

### 9.2 应用集成测试

- 运行状态下拒绝预检或导入。
- 预检无副作用。
- 预检后文件变化时拒绝导入。
- 任意错误时原目录、节点和服务器配置保持不变。
- 成功导入时目录和节点一次性替换，服务器配置保持不变。
- 保存并重新加载 `.opcuaproj` 后，数字 NodeId 类型保持不变。
- 加载未包含 `node_id_kind` 的旧项目时仍按字符串 NodeId 解释。

### 9.3 前端测试

- 仅在 `Stopped` 状态启用导入按钮。
- 文件取消选择不触发错误或状态变化。
- 正确显示预检统计、警告和逐行错误。
- 有错误时不能确认导入。
- 最终替换提示清晰，成功后节点表立即刷新。

### 9.4 真实应用验证

1. 使用包含中文、只读点、可写点和参考类型别名的 CSV 导入。
2. 启动真实子站并记录实际命名空间索引。
3. 使用 OPC UA 主站浏览自动生成的目录层级。
4. 读取 `ns=<实际索引>;i=48` 和 `ns=<实际索引>;i=10417`。
5. 验证只读点拒绝写入，可写点能够写入且值可再次读取。
6. 保存项目、关闭并重新打开应用，再次启动并复核相同数字 NodeId。

## 10. 验收标准

满足以下条件视为完成：

1. 用户能用固定 8 列 CSV 导入标量点表。
2. CSV 中的数字 `opcua_id` 在运行时表现为当前应用命名空间下的数字 NodeId。
3. 目录按 `folder_path` 确定性生成。
4. 任何输入错误都能定位到明确行和字段，且不会产生部分导入。
5. 导入只在子站停止时进行，并原子替换目录和节点。
6. 端点、安全、用户、证书和其他服务器配置保持不变。
7. 旧 `.opcuaproj` 文件兼容，新项目能持久化数字 NodeId 类型。
8. 真实子站与主站验证通过读、写、重启和项目往返场景。
